# P(-1) review — 2026-11-09 (0.7.2)

**Scope.** Everything whirl ships after the toolchain bumps of 0.6.14 – 0.7.1
(cyrius 6.6.2 → 6.7.18, taar → 0.6.2):
- the eleven `src/` modules;
- the unit suite, the behavioral suite, the AGNOS probe and its harness;
- CI;
- the docs.

This is whirl's first filed audit. Earlier security passes (0.6.6, 0.6.8) are
recorded in the CHANGELOG. The question this one answers is what is wrong,
missing or untested in what whirl already ships. New features are out of scope
unless a finding needed one.

**Method.** The P(-1) steps, in order:
0. **Intent.** The roadmap, `state.md`'s open defects, and the CHANGELOG since
   0.6.6.
1. **Cleanliness.** `cyrius audit` (format, lint, docs, tests). It passed at
   0.7.1, the first release where it did.
2. **Benchmark baseline.** whirl had no benchmarks. `benches/parse.bcyr` was
   written and run three times before any repair.
3. **Internal deep review.** Every line of `src/`. Two further reviews ran in
   parallel without seeing this one's findings, so neither could anchor on it.
   One took a security and correctness lens, the other robustness, memory,
   performance and refactoring. Each confirmed its findings against a built
   binary and local test servers before reporting. All three reviews
   independently found the chunk-size overflow (B), the unchecked 206 (C) and
   the stdin cap (D). The security review alone found the cwd write (A).
4. **External references.** RFC 9110 (§7.1 fragments, §9.2.2 idempotent
   methods, §15.4 redirects), RFC 9112 (§6.3 framing, chunked coding),
   RFC 9309 (robots.txt), and the cyrius 6.7.x stdlib (`tls_native` EOF
   semantics, `set_ca_system` caching, per-arch `O_NOFOLLOW`).
5. **Repairs.** Behavioural fixes have a check in `tests/behavior.py`. Each new
   check has a control that reproduces the defect on 0.7.1, so it is known to
   exercise the path. Gaps are listed under *Deferred*.
6. **Post-repair benchmarks and verification** on every target (below).
7. **Documentation audit**: comments, README, roadmap, `state.md`.

**Result.** 23 findings: 1 high, 10 medium, 8 low, 4 info. All are repaired in
0.7.2. Further items are deferred to the roadmap with their reasons.

## Findings

**A — `-r` wrote into the cwd.** `tree_relpath` refused `..`, so nothing escaped
the cwd, but the cwd itself was the mirror. A crawled page could name any
relative path in it: a project's build files, or a dotfile in `$HOME`. Run from
a source tree or a home directory, that is a path to code execution.
*Fix:* the mirror lives in `./HOST[:PORT]/` (`tree_host_dir`), which is wget's
layout. Any path segment that begins with `.` is refused (`_path_segments_safe`),
which covers `..` as before and every hidden name. The per-host directory
cannot be `.`, `..` or dot-leading.
*Test:* [16]. A pre-existing file in the cwd is untouched, the page lands under
`./127.0.0.1:PORT/`, and the hidden path is not written. Control: 0.7.1
overwrites the cwd file.

**B — chunk-size overflow.** The hex parse had no digit limit. A long enough
size wrapped i64 negative, and `_http_chunked_terminated` then added it to its
cursor. The completeness check runs after every recv, on every fetch, so any
server could reach it.
*Fix:* one parser, `_http_chunk_size`, serves the walker and the decoder: at
most 15 hex digits (2^60, far past any body whirl holds), and it reports a line
whose end has not arrived. `_http_chunk_walk` treats a chunk larger than the
bytes present as "not yet", and its cursor only moves forward.
*Test:* none dedicated in this release (see *Deferred*). The existing
`response-complete` unit group and every chunked check in `behavior.py` pass on
the new parser.

**C — the `-C` 206 path.** It appended `rbuf` after the headers as it stood.
Three outcomes followed, each with exit 0: a chunked 206 left its framing in
the file, a short 206 was appended as if complete, and a range starting
elsewhere was appended at the wrong offset. The append was also a single
unlooped write.
*Fix:* `_resume_append` runs the truncation check, requires a `Content-Range`
whose first byte equals the local size, decodes through `http_decode_body`,
and appends with a looped write. A 416 whose stated length differs from the
local file is an error, and Range goes out on every redirect hop.
*Test:* [19]: wrong start refused, chunked decoded, short refused (file
unchanged), correct 206 appended. Control: 0.7.1 appends the wrong range.

**D — `-d @-` cap.** stdin was read into 256 KiB and stopped there, with no
error. The `@file` path was given a 1 MiB cap and an error at 0.6.6; this path
was missed, and a read error also ended the body as if it were EOF.
*Fix:* `_cli_read_fd` uses `CLI_BODY_MAX` + 1 and the same TOOBIG refusal, and
treats a read error as unreadable.
*Test:* [18]: 300,000 bytes arrive whole; over 1 MiB, exit 2 and nothing sent.
Control: 0.7.1 sends 262,144.

**E — stdout errors.** `output_write` to stdout ignored `sys_write`'s result.
*Fix:* `_output_write_fd` loops and fails on an error or on no progress. The
`-C` append uses it too.
*Test:* [22]: stdout on `/dev/full` exits 9.

**F — crawl exit status.** `_crawl` returned 0 unconditionally.
*Fix:* `mirror_crawl` returns 9 when anything failed or nothing was saved, and 2
when the host cannot name a directory. A redirect is reported but not counted
as a failure, since `-r` does not follow them yet (roadmap 0.8.x).
*Test:* [17]: a 404 start URL exits 9; a clean crawl exits 0. Control: 0.7.1
exits 0.

**G — crawl cap.** Links were de-duplicated only against pages already fetched,
and filtered for origin and robots.txt only when dequeued. Duplicates and
off-origin links filled the 64 slots.
*Fix:* each link is resolved, origin-checked, robots-checked, path-checked and
canonicalized (origin plus path, without the fragment) before it is queued.
The queue is the de-duplication set.
*Test:* [17]: a link repeated 40 times is fetched once, with no cap message.

**H — retry policy.** Every `total <= 0` was retried, TLS failures included,
and so was a POST the server had already received.
*Fix:* `transport_fetch_retry` retries failures before the request went out
(resolve, socket, connect, send), and an empty response only for an idempotent
method (RFC 9110 §9.2.2). It does not retry TLS failures, as curl does not.
*Test:* [22]: a sent POST goes out once (control: three times on 0.7.1). The
TLS case was verified by hand: a self-signed server under `--retry 3` was
refused in 16 ms, with no backoff.

**I — redirect methods.** `hops > 0` forced `GET` with no body, for every
status. The HEAD flag was global, so `-I -L` sent GET while still reading the
response as header-only.
*Fix:* `_redirect_method` applies RFC 9110 §15.4. The body is kept only when the
method is unchanged. The no-body flag is set per request from the method sent,
and the crawl clears it.
*Test:* [20]: 307 keeps POST and its body, 303 sends a bodyless GET, `-I -L`
stays HEAD. Control: 0.7.1 sends GET on the 307.

**J — unfinished redirects.** The hop limit and an unfollowable `Location` both
fell through to writing the 3xx body, exiting 0 with "(use -L to follow)".
*Fix:* under `-L`, both exit 9 with a specific message.
*Test:* [20]: the redirect loop exits 9 with "too many redirects". Control:
0.7.1 exits 0.

**K — memory.** The crawl allocated a 1 MiB decode buffer per chunked page.
`links_path_normalize` allocated a fixed 2 KiB table per call. `main` allocated
the receive buffer before the `-r` branch, which does not use it.
*Fix:* one lazily allocated decode buffer (`util_scratch`); a table sized from
the path's segment count (which also removes a 256-segment limit); the buffer
allocated after the branch.
*Measured:* peak RSS for a 61-page chunked crawl fell from 67,772 KB (0.7.1) to
11,480 KB.

**L — quadratic completeness check.** After each recv the check rescanned the
header terminator and the whole chunk stream from offset 0.
*Fix:* `http_complete_feed` keeps its scan positions, so each byte is examined
a bounded number of times. Interim responses are handled in the same pass.
*Measured:* see *Benchmarks*.

**M — robots.txt failed open.** Each failure meant "no rules": the 5xx case,
transport failures, and redirects. Several parse flaws made rules match
nothing. A second `User-agent:` line reset group membership. Comments, tabs and
trailing whitespace were kept in the value. `*` and `$` were literal. A chunked
body was parsed with its framing. Rules past 64 were dropped silently, and the
body was capped at 64 KiB.
*Fix:* RFC 9309 throughout. A 5xx or no answer means disallow, and the crawl
stops with exit 9. A 4xx means no rules. Up to five redirects are followed.
Groups combine consecutive `User-agent:` lines, and a `whirl` group overrides
`*`. Values are trimmed and comments cut, and wildcards are honoured. The body
is decoded, read up to 512 KiB, and parsed into up to 256 rules, with any excess
reported.
*Test:* [21]: a rule shared by two `User-agent:` lines is honoured, and a 5xx
robots.txt crawls nothing and exits 9. Control: 0.7.1 fetches the disallowed
page.

**N — unescaped stderr.** The unfollowed-redirect message printed the raw
`Location` value, so terminal control sequences reached the user's terminal.
*Fix:* `util_eputs_safe` prints C0 controls and DEL as `?`, the rule dig and
cmdit use. Every server-derived string in a message goes through it. C1 bytes
pass through, because replacing them would mangle UTF-8, and UTF-8 terminals do
not act on a lone C1 byte.
*Test:* none dedicated (see *Deferred*).

**O — half header blocks.** `_response_truncated` returned 0 when the
terminator was missing.
*Fix:* `http_response_truncated` treats it as truncated, so `-i` and `-I` exit
9.

**P — 1xx, 204 and 304.** A 103 Early Hints was taken as the final response.
A 204 or 304 without a length header was read as close-delimited.
*Fix:* the completeness pass skips interim responses (101 excepted), and the
transport moves the final response to offset 0. 204 and 304 are complete at
their headers.
*Test:* [22]: a 204 completes in under 5 s while the server holds the
connection open.

**Q — URL parsing.** Only `/` ended the authority, the fragment went into the
request line, and the scheme was matched case-sensitively.
*Fix:* `url_parse` ends the authority at `/`, `?` or `#`, drops the fragment,
and matches the scheme case-insensitively. `url_filename` and `tree_relpath`
cut at `#` too.
*Test:* [22]: `page.html#section` requests `/page.html`.

**R — smaller redirect and crawl defects.** A `Location` with trailing
whitespace stopped the redirect, because `url_parse` refuses whitespace. The
crawl compared hosts with `streq`. A `?query` link resolved against the
directory, not the page.
*Fix:* `http_header_dup` trims. The crawl uses `_same_origin`. `_resolve_link`
and `_abs_location` handle `?`.

**S — deadline unchecked.** taar 0.6.2 made the timeout bound connect and send
as well as recv, and whirl ignored whether it was set.
*Fix:* `_transport_connect` refuses a socket that will not take it.

**T — empty POST body.** `bodylen > 0` gated `Content-Length`.
*Fix:* a body that was given, even an empty one, gets `Content-Length`.

**U — undifferentiated errors.**
*Fix:* `transport_strerror`. Verified by hand: an unknown host prints `could not
resolve host <name>`.

**V — refactor.**
- **Duplication removed:** body decode, the TLS-or-plain dispatch and the
  case-insensitive matcher existed two or three times each. The two copies of
  the decode that were missing it explain C and M.
- **Module split:** the crawl's I/O moved into `src/mirror.cyr`, leaving
  `crawl.cyr` pure.
- **Named limits** replace magic numbers.
- **Dependencies:** `flags` was never called, and `dynlib` / `fdlopen` have
  arrived through `tls.cyr` since cyrius 6.6.9, so all three were dropped.
  `assert` and `bench` moved to `[test]`. The binary is 1,184 B smaller.

**W — docs.** Corrected:
- "HTTPS … next bite" and "flat file";
- a claim that the TLS dispatch keyed on a global (it keys on each ctx);
- "O_NOFOLLOW … out of scope";
- partial usage strings;
- the README's claims of binary/text auto-detection and default
  redirect-following (neither exists), and of taar `tls` / `http` modules
  (unwritten).

## Deferred

Each is in [`roadmap.md`](../development/roadmap.md).

| Item | Why not now |
| --- | --- |
| dedicated regression tests for B, N, O, the 1xx half of P, R, S, T | the repairs are reviewed and pass every existing check, but have no test that fails without them; 0.8.x |
| `--retry` on 408 / 429 / 5xx and on truncated bodies | feature work beyond the repair of H; 0.8.x |
| `-r` following redirects | feature work; a redirect is reported and not counted as a failure meanwhile |
| a close-delimited body of exactly 1 MiB reads as truncated | the 1 MiB buffer itself; D1 streaming (0.8.x) |
| duplicate or conflicting `Content-Length`, TE with CL, bare-LF headers | a strictness decision (RFC 9112 §6.3) |
| B5: a symlinked directory inside the mirror, the per-host directory included | needs a per-component `openat` walk; requires local write access to the cwd |
| B2: AGNOS symlink refusal is a pre-check | blocked on an agnos `open` flag |
| `-r` silently ignores `-o`, `-O`, `-C`, `-i`, `-I` | becomes usage errors with the cmdit adoption |
| `-I -L` prints only the final response's headers | accepted; curl prints each hop (post-v1) |
| C1 control bytes pass the stderr escape | accepted: escaping them would mangle UTF-8 |
| AGNOS physical memory (2 MB mmap granularity) | suspected higher than the Linux figure; not measured |

## Benchmarks

`benches/parse.bcyr`, x86_64. The host's timer floor (about 1.3 µs per clock
read) is measured and subtracted by `lib/bench.cyr`. Medians of three runs:

| Row | Before | After | |
| --- | ---: | ---: | --- |
| `url_parse` | 262 ns | 337 ns | case-insensitive scheme, authority and fragment scans (Q) |
| `http_build_request` (GET, 2 headers) | 451 ns | 414 ns | noise |
| `http_content_length` | 422 ns | 368 ns | shared matcher |
| `http_response_complete` (64 KiB, Content-Length) | 888 ns | 951 ns | reset + feed |
| `http_response_complete` (4096 one-byte chunks) | 76.7 µs | 96.0 µs | bounded parser (B); one stateless call |
| `http_dechunk` (4096 one-byte chunks) | 91.8 µs | 105.0 µs | bounds checks (B) |
| `links_extract` (64 KiB page, 64 links) | 485 µs | 439 µs | shared matcher |
| `links_path_normalize` | 342 ns | 195 ns | no fixed 2 KiB table (K) |
| `tree_relpath` | 191 ns | 206 ns | hidden-segment check (A) |
| `robots_parse` (2 groups, 4 rules) | 669 ns | 1,003 ns | RFC grouping and trimming (M) |
| `robots_blocked` | 70 ns | 218 ns | wildcard matching (M) |

The single-call rows got slower by tens to hundreds of nanoseconds, the cost of
the bounds and the RFC behaviour, on paths that then wait milliseconds on the
network. What the read loop actually does, one completeness call per arriving
chunk, is a row of its own, added with the repair:

| Row (4096 one-byte chunks, one call per chunk) | Time |
| --- | ---: |
| incremental check (0.7.2) | ~141 µs |
| stateless check, the pre-0.7.2 loop shape | ~194 ms |

Roughly 1,400 times faster at this size. The gap grows with the square of the
chunk count.

## Verification at 0.7.2

- `cyrius audit`: format, lint and docs clean, tests passing.
- `cyrius test`: 139/139 on x86_64, and 139/139 on aarch64 via
  `cyrius test --aarch64`.
- `tests/behavior.py`: 49/49 standalone and 57/57 against 0.7.1, each control
  reproducing its defect. 49/49 for the aarch64 build under qemu-user. The
  `O_NOFOLLOW` negative control (x86_64's value planted in the aarch64 arm)
  fails exactly check [13]'s two assertions, so [13] still exercises the flag
  in the per-host directory.
- Builds: x86_64, `--agnos` and `--aarch64` with no warnings, and the agnos arm
  selected. A CI-faithful run (tracked and new files only, no `lib/`, no
  siblings) wrote an identical lock and sha256-identical host and agnos
  binaries.

  656 B per connect). agnos's `whirl-smoke.sh`, run from a throwaway copy of its
  tree, passed `--help`, HTTP and HTTPS. An added step, the first `-r` run on

- Live, x86_64:
  - `http://` and `https://example.com` are byte-identical to 0.7.1;
  - `-L https://github.com` completes;
  - a blackholed host fails in 10.2 s;

  - a local self-signed server is refused, exit 9.
